= Automated Publishing System
:toc:
:icons: font

This system provides a dynamic, configuration-driven orchestrator to build and aggregate various subprojects into a single GitHub Pages-ready `docs/` folder.

== Publishing Strategy

To ensure control over when the site is updated and to avoid automatic republishing on every commit, the following strategy is implemented:

1. **Local Build Isolation**: The `docs/` directory is ignored by Git (`.gitignore`). Running `publish.ps1` locally prepares the site for preview or manual inspection without affecting the repository or the live site.
2. **Remote Publish**: A GitHub Actions workflow (`.github/workflows/publish.yml`) is provided. It can be triggered in three ways:
* **Manually**: Via the GitHub "Actions" tab (using `workflow_dispatch`).
* **Tagging**: Pushing a tag starting with `web-v` (e.g., `web-v1.0.0`).
* **Commit Message**: Including `[publish]` in your commit message on the `main` branch.
3. **Dedicated Branch**: The live site is served from the `gh-pages` branch. The manual workflow builds the projects and pushes the results to this branch.

This setup prevents "random commits" from triggering a redeploy and gives you full control over the publishing lifecycle.

== GitHub Configuration

After setting up the workflow, you must perform a one-time configuration on GitHub:

1.  Navigate to your repository on GitHub.
2.  Go to **Settings** > **Pages**.
3.  Under **Build and deployment** > **Source**, ensure **"Deploy from a branch"** is selected.
4.  Under **Branch**, select `gh-pages` and the `/ (root)` folder.
5.  Click **Save**.

NOTE: The `gh-pages` branch will be created automatically the first time the workflow runs successfully. If you don't see it in the dropdown yet, trigger a manual publish first.

== Overview

The system consists of a main PowerShell orchestrator (`.publish/publish.ps1`) that crawls the repository for project-specific configurations (`publish.json`), executes defined workflows to build them, and generates a terminal-inspired overview page linking all successful builds.

== Components

* `.publish/`: Internal system directory.
** `publish.ps1`: The main entry point and orchestrator.
** `Workflows.psm1`: PowerShell module containing build logic (e.g., `npm-webpack`).
** `Assets/`: Templates for the overview page (`index.html`, `style.css`, `app.js`).
* `publish.json`: Local configuration file required in each subproject's web root.

== How to add a new project

1. Create a `publish.json` file in your project's web root:
+
[source,json]
----
{
  "name": "my-project",
  "description": "Short description for the overview page.",
  "workflow": "npm-webpack",
  "distDir": "dist",
  "buildCmd": "npm run build"
}
----

2. Run the publishing script from the project root.

== Usage

Run the script from the root of the mono-repo:

[source,powershell]
----
.\.publish\publish.ps1 [switches]
----

=== Available Switches

[cols="1,3"]
|===
| Switch | Description

| `-Preview`
| Builds the site and starts a local web server (via `npx serve`) to preview the result.

| `-Parallel`
| Builds projects concurrently. Requires PowerShell 7+. Falls back to sequential building on older versions.

| `-ConfigFile <path>`
| Bypasses the crawler and uses a specific JSON configuration file.
|===

== Advanced: Using the `-ConfigFile` Switch

The `-ConfigFile` switch allows you to provide a specific configuration file (or a list of project configurations), which is useful for building subsets, handling variants, or CI/CD integration.

When using this switch, the script skips crawling and expects the JSON file to contain the project metadata.

=== Manual Config Example

Create a file (e.g., `subset.json`):

[source,json]
----
[
  {
    "name": "vn-clock",
    "description": "Clock subset build",
    "workflow": "npm-webpack",
    "distDir": "dist",
    "buildCmd": "npm run build",
    "SourceDir": "rust/vn-clock/vn-clock-web/site"
  }
]
----

NOTE: When using `-ConfigFile`, you **must** include the `SourceDir` property for each project so the script knows where the project root is located relative to the repo root.

Run with:

[source,powershell]
----
.\.publish\publish.ps1 -ConfigFile "subset.json"
----

== Project Overview Page

The generated `docs/index.html` is a "terminal-inspired" page with the following features:

* **Keyboard Navigation**: Use `↑`/`↓` (or `J`/`K`) to select projects, and `ENTER` to open.
* **Help Overlay**: Press `H` or `?` to toggle the keyboard shortcuts help menu.
* **Accessibility**: Fully semantic HTML with ARIA roles for screen reader support.
* **Mouse Support**: Click to select/open projects and use the Help button.
